## 순서 및 범위
기본적으로 ID 순서로 진행한다. 단, 앞 작업이 외부 입력에 막히면 의존성이 없는 하위 작업을 먼저 수행한다. 실제 기기 없이 가능한 검증과 기기가 필요한 검증을 분리한다. 누적 목표 비율을 달성하려고 불안정한 코드를 추가하지 않는다.
GPT-01~03 GO(개발 기반). GPT-04 PARTIAL; GPT-05 독립 준비 PARTIAL. GB-01 통합 완료; GB-02 독립 준비 가능. GPT-06 PARTIAL / 독립 준비 종료·중단. GPT-07 미착수, 사용자 별도 승인 대기. 실제 상태는 STATUS.md가 정본이다.
GPT-02~12는 사전 범위다. 시작 직전에 관련 실제 코드·공식 API·의존성을 확인하여 상세 WO 또는 GPT 작업 명세를 작성한다. 무효화된 과거 계획을 그대로 실행하지 않는다.
사용자가 "다음 작업"이라고 하면 위 표와 STATUS, BLOCKERS에 따라 안전한 작업을 선정한다. 순서 변경은 근거와 선행 조건을 WORK_LOG에 남긴다.

## 통합 품질 검증 및 최종 감사 — 사용자 승인 개정 (2026-11-28)
GPT-06 종료 중간 감사 및 개선(현재) → GPT-07~09 개발 및 단계별 검증 → GPT-09 종료 변경 영향 중심 통합 품질 검증 → GPT-10~12 개발 및 단계별 검증 → GPT-12 종료 전체 최종 감사. 2차 전면 중간 감사는 별도 반복하지 않는다. GPT-09에서는 신규 데이터·권한·FSM·외부 공급원·모션 보호·모듈 통합, 변경 영향 회귀 및 미해결 필수 차단점을 검증한다. 기존 검증 증거는 대상·환경·계약이 동일할 때 재사용한다. 공급망·빌드·그래픽 등은 관련 변경, 새 보안 위험, 증거 불일치 또는 미해결 필수 항목이 있을 때 재검증한다. 필수 G0~G7, 출시 기준, 기존 차단점 및 GPT-07 별도 승인 유지. 실제 기기/외부 권한 필요 검증은 NOT RUN으로 유지하고 승인된 환경에 이관한다. GPT-12는 전체 출시 적합성을 검증한다. 결함별 해결/차단/선택 개선을 분리한다. 필수 게이트 전 통합 GO 금지. 이 개정은 기능 착수, 실기기 설치, PR 병합 또는 기준 완화 승인이 아니다.

## 에이전트 가용성 및 최종 감사 — 사용자 합의 (2026-11-28)
Grok Build/Antigravity는 사용량 소진 시 약 1주간 이용 불가할 수 있는 추가 자원이다. 상시 가용 또는 회복일을 보장하지 않는다. 독립 소유 경로·짧은 인계 단위로 배정한다. 소진 시 마지막 SHA, 증거, 미완료 범위, 재개 조건을 보존한다. 막히지 않은 독립 작업을 우선한다. 필수 선행 작업 인수는 사용자 승인, 기존 담당 정지, 정확한 브랜치/로컬 상태 확인, 충돌 없는 소유권 재배정 후 진행한다. 접근 불가능한 로컬 변경을 추측하거나 덮어쓰지 않는다. 회복 시 최신 기준으로 재배정한다. 두 모델의 참여 자체는 감사 필수 종료 조건이 아니다. 필수 기술 검증 및 독립 검토 요건은 유지한다. Codex는 필요한 로컬/고난도 작업에 조기 제한 투입 가능하며 GPT-09 이후 통합 검증에 본격 참여한다. GPT-12 및 최종 전면 감사는 가용한 GPT-6.2 Codex(사용자 표기 6.2 SOL) 중심으로 실행·수정·실기기 검증을 수행하고 채팅 GPT는 총괄·독립 검수·증거 대조를 지원한다. GB/AG가 가용하면 각 전문 분야 읽기 전용 독립 감사 및 재현 증거 제출을 맡긴다. 수정은 단일 소유자에 집중한다. 모델 제공·사용량·실기기 접근과 실제 검증 증거에 따라 배정하며, 기능 착수/병합/실기기 변경 승인으로 간주하지 않는다.
