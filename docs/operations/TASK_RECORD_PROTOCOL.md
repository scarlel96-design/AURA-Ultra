# 작업별 영속 기록 규정 v1.1

## 적용 범위
모든 GPT 작업, WO, 긴급 수정, 조사, 검증, 문서 변경에 적용한다. 코드 변경이 없어도 기록한다. 대화 기억은 정본이 아니다. 저장소의 요구사항·기술 명세·결정·실제 코드·검증 증거를 읽어 재개한다.
이 문서와 [VERIFICATION_PROTOCOL.md](VERIFICATION_PROTOCOL.md)는 매 작업의 필수 규정이다.

## 1. 작업 전 기록
작업 ID와 회차를 부여한다. 같은 작업의 재시도는 기존 ID 아래 새 회차로 기록한다.
관련 증거 경로에 REPORT.md 또는 회차별 REPORT-NN.md를 만든다. [TASK_REPORT_TEMPLATE.md](TASK_REPORT_TEMPLATE.md)를 적용한다. 기존 시험 기록을 덮어쓰지 않는다.
기록할 정보:
- 현재 HEAD, 대상 브랜치, 작업자, 담당 파일, 작업 범위, 제외 범위.
- 사용자 요구사항 ID, 관련 WO/GPT ID, 설계 계약, 참조 문서 경로 및 버전.
- 직전 작업의 산출물, 미해결 장애, 의존성, 진입 조건, 예상 영향 범위.
- 성공 조건, 검증 명령, 예상 결과, 필수/선택 시험, 실패 판정 및 롤백 방법.
- 공식 API 및 외부 자료의 정확한 링크, 조회 시점, 적용 버전, 라이선스, 확인한 사실과 미확인 사항.
- 결정 사항, 대안, 근거, 가정 및 승인 필요 여부.

작업 중 새 제약이나 중요한 결정이 생기면 해당 기록을 즉시 갱신한다. 대화에만 남기지 않는다. 저장소에 쓰지 못하는 환경에서는 변경을 완료로 주장하지 않는다.

## 2. 구현 및 변경 기록
파일별 책임과 변경 이유를 기록한다. 새 인터페이스, 데이터 형식, 설정, 생성 도구, 빌드 명령, 실행 및 사용 방법을 실제 코드와 함께 갱신한다.
버전별 기능 차이와 fallback을 기록한다. 지원되지 않는 기능을 정상 구현으로 기록하지 않는다.
새 의존성에는 버전, 출처, 라이선스, 도입 이유, 알려진 위험을 기록한다. 생성 자산은 원본 경로, 생성 명령, 도구 버전 및 재생성 방법을 기록한다.
기술 결정 변경은 ADR로 관리한다. 사용자의 새로운 요구사항은 PROJECT_INVARIANTS와 관련 정본 명세에 반영한다. 충돌은 발견 즉시 해결하거나 차단점으로 기록한다.
실패한 접근도 원인, 재현 조건, 폐기 이유와 함께 기록한다. 같은 실패를 다음 세션에서 반복하지 않는다. 비밀키, 계정 토큰, 실제 건강 및 정밀 위치 데이터는 기록하지 않는다.

## 3. 작업 종료 체크포인트
검증 규정의 모든 적용 항목을 검사한다. 다음 정보를 REPORT 및 정본 문서에 반영한다.
- 변경 파일 및 기능, 코드 SHA, 요구사항-시험 추적표, 검증 결과와 원본 증거.
- 검토 결과, 발견한 문제 및 심각도, 수정 결과와 재검증 결과.
- 미실행·실패·진행 중 시험, 제한 사항, 남은 작업, 재개 명령.
- 다음에 읽을 파일, 실행할 명령, 예상 결과, 다음 작업 ID 및 진입 조건.
- 판정(GO/PARTIAL/NO-GO)과 판정 근거.

매 작업 종료 전 STATUS.md, WORK_LOG.md, BLOCKERS.md 및 해당 evidence를 갱신한다. 새 장애가 없어도 확인 결과와 변경 없음 사유를 REPORT에 적는다. ROADMAP, GPT_EXECUTION_PLAN, HANDOFF, 기술 명세는 변경된 사실이 있을 때 동기화한다.
사용자가 제공한 새 결정과 제약이 요구사항 정본에 반영되었는지 확인한다.
문서의 상대 경로, 참조 ID, 변경 SHA, 보고서의 시험 결과와 원본 로그를 대조한다. 실제 main 또는 승인된 작업 브랜치에서 파일 존재 및 반영 여부를 확인한다.
작업 종료 시 저장소에 기록하지 못했으면 이유와 유실 위험을 사용자에게 알린다. 완료 또는 인계 가능으로 판정하지 않는다.

## 4. 재개 복구 시험
이전 대화 없이 AGENTS → STATUS → 작업 규정 → 활성 작업 명세 → 최신 evidence → 실제 소스·CI를 따라가면 다음 작업을 수행할 수 있어야 한다.
필수 정보 누락, 끊어진 참조, 서로 다른 완료 판정, 오래된 검증 SHA가 있는지 확인한다. 발견 시 수정한다.
복구 확인은 문서 기반 경로 점검이다. 실제 다른 세션이나 다른 에이전트로 시험하지 않았다면 그렇게 표현하지 않는다.

## 5. 보관
커밋된 코드와 연결되는 증거의 SHA를 유지한다. 자기 참조 커밋 SHA를 기록하지 않는다. CI 링크와 시험 명령·결과·핵심 로그 발췌를 남긴다. Artifact 만료에 대비해 재생성 절차를 기록한다. 대용량·민감 로그는 저장소에 그대로 넣지 않는다.
보고서 정정은 이전 기록을 보존하고 정정 사유와 새 증거를 추가한다.
