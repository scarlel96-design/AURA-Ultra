## 구현 및 시험
1. 공식 WFF4 Variant 전환의 지원 속성/보간, duration/startOffset 의미를 확인한다. 동일 시간 객체의 위치·크기 연속성을 표현하는 최소 XML 샘플을 작성한다. WFF2/3 정적 AOD 대체 샘플을 작성한다.
2. WFF4 Reference의 허용 데이터 필드와 사용 위치를 공식 문서 및 스키마로 확인한다. 합성 complication 데이터로 여러 그래픽 요소를 변경하는 최소 샘플을 설계한다. 지원되지 않는 임의 상태 전달은 금지한다. 필요 시 provider는 독립 실행 앱으로 분리하며 PoC 범위를 넘는 통합은 하지 않는다.
3. WFF5 Group/ComplicationSlot blend 등 문서로 확인한 상위 기능 중 최소 1개를 별도 XML로 검증한다. 하위 규격에 상위 전용 기능이 들어가면 검출되는지 실패 fixture로 확인한다. Gyro/숫자 전환은 공식 조건과 대체안만 기록한다.
4. 고정된 공식 validator 및 memory evaluator를 사용한다. 대상별 정상/잘못된 XML, 최소 샘플의 clean APK 빌드, 리소스 전용·Manifest·원본 XML·메모리(활성70/AOD7 MiB)·Debug 서명 검증을 수행한다. 신규 라이브러리/비공개 API/실행 코드 삽입 금지.
5. 이미 사용 가능한 격리 Wear OS 에뮬레이터에서 호환되는 APK의 설치·선택·렌더링·AOD 전환을 검증한다. 기기 모델/OS/API/해상도, APK SHA, ADB 명령, 캡처/영상 및 실패 로그를 기록한다. 실제 사용자 워치는 읽기 전용 환경 확인만 허용하며 설치/설정 변경은 별도 승인 필요. 새 SDK/에뮬레이터 다운로드, 유료 서비스, 계정 권한 변경 등 추가 환경 조치는 사용자 승인 없이 하지 않는다. 환경이 없으면 NOT RUN, 구체적인 재현 절차와 필요한 환경을 남긴다.
