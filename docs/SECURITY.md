# 보안·개인정보·복구
## 위협 모델
외부 API 응답 위조/오류, 권한 철회, 키 유출, 건강/위치 데이터 노출, 앱 충돌, 변조된 업데이트, 종속성 공급망, 잘못된 설정 및 오래된 데이터 적용.

## 요구사항
- 필요한 시점에 최소 권한만 요청한다. 권한을 거부해도 기본 페이스를 유지한다.
- 건강·위치 데이터는 목적에 필요한 범위만 저장한다. 원시 건강 정보와 정밀 위치를 로그에 기록하지 않는다.
- HTTPS 및 정상 인증서 검증을 사용한다. 응답 스키마, 범위, 크기, 날짜를 검사한다.
- 비밀키를 소스, APK 리소스, 로그, CI 산출물에 저장하지 않는다. 공개 클라이언트 키는 비밀이 아님을 전제로 제한하거나 적절한 중계 방식을 검토한다.
- 설정과 캐시를 앱 전용 저장소에 둔다. 민감 데이터에는 필요한 경우 플랫폼 Keystore 기반 보호를 적용한다.
- Data Layer에 필요한 데이터만 전달한다. 패키지·서명 조건 및 사용자 연결을 확인한다.
- 서명된 업데이트와 versionCode 정책을 적용한다. 이전 설정의 호환성 및 손상 복구를 검증한다.
- 종속성 버전, 라이선스, 취약점 및 원본 자산 출처를 기록한다. 비공개 API 및 우회 권한을 금지한다.
- 배포용 서명키를 저장소에 커밋하지 않는다. 로컬 테스트와 출시 서명을 분리한다.

## 복구
데이터 공급원 장애 시 캐시와 갱신 시각을 표시한다. 값이 없으면 unavailable을 표시한다. 권한 철회 시 해당 데이터 접근을 중단하고 저장 정책에 따라 정리한다. 설정 손상 시 마지막 유효 설정 또는 안전 기본값을 적용한다. 앱 장애가 WFF 시간 표시에 영향을 주지 않게 한다.
건강 데이터는 일반 웰니스 정보다. 의료 진단 기능으로 표현하지 않는다.

## 검증
권한 거부/철회, 오프라인, 잘못된 응답, 만료 캐시, 앱 종료, 재부팅, 재연결, 설정 손상, 패키지 업데이트를 시험한다. 보안 실패는 출시 차단 조건이다.
