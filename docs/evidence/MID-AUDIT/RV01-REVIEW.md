## Static defects (not newly executed product red tests)
RV01-C1 P1 candidate boundary: Authority.kt 237-248 checks capability.seal identity, session, request, records[capability.scope], state and generation, but not capability issuance identity. 338-345 internal constructor and readable internal seal/sessionToken enable same-module code to construct a capability using a real token's seal, current generation from view, altered request/scope or arbitrary acquisitionId. A holder of an old capability after revoke/regrant can construct a new-looking token without acquire; a same-generation clone can also pass. This violates ADR-008 non-retagging/structural fabrication requirement. Existing capabilityConstructionAndCopyCannotForgeAcceptance checks only Any() seal and lack of copy; no same-seal clone. No reflection or hostile arbitrary JVM execution required for the Kotlin same-module scenario. Do not claim a real SDK leak; no integration exists.
RV01-C2 P1 candidate boundary: permits(capability, request) has no expected scope argument; AuthorityRequest equality is only stream. A valid scope A capability can satisfy a caller checking same stream for scope B even if B is denied, because lookup uses A. Existing foreignScopeSessionAndRequestAreRejected uses two coordinators and different streams, not same coordinator/same stream/different scope. Require independent trusted expected scope and request at verification, no scope-free overload. Bind request identity or define stream vs acquisition identity precisely; actual result-to-value binding deferred per RV01. Old coordinator remains active in restartRequiresFreshAuthority (line 218); lifecycle disposal and unique production session allocation are explicitly deferred to trusted adapter, not proof of restart-wide revocation. Do not expand this pure candidate into SDK/persistence/consumer implementation.
