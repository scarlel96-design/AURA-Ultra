# Signature basic capture checks (GPT-04 R07)

Run `python tools/check_signature_capture.py capture.png --diameter 432 --mode ambient --hour-format 24`.
Use an original square, opaque 8-bit RGB/RGBA PNG, non-interlaced, without overlays or rescaling. The four supported diameters are 432, 438, 480 and 498. The inspector reads the schema 2 layout and tests the expected visible regions. It rejects a blank capture, nonblack pixels outside the circular display or expected text regions, missing region pixels, and an AOD nonblack fraction above 10% of circular pixel centers. Every nonzero RGB channel counts, including dim antialiased pixels. The 10% is the existing project target, not an official validator or a power measurement. The basic candidate has a black background; do not use this strict text-region policy on future decorative themes. No color management, OCR, text identity, correct capture provenance, frame analysis, display luminance or actual readability is established. A single pixel in a region is not proof of readable text. Capture mode and hour format are operator inputs; prove those independently during runtime tests. Reject unsupported encodings instead of converting them silently. The PNG reader uses a bounded standard-library subset and does not modify inputs. Keep actual screenshots containing personal data outside the repository. Save the JSON and capture SHA-256 with the device, OS, build SHA, APK hash, mode and test setup in private test evidence. Exit 1 indicates failure. Unit fixtures are synthetic, never device screenshots.

Run `python -m unittest discover -s tests/unit -p test_signature_capture.py -v`. Existing Bootstrap CI discovers the new tests without weakening existing gates. The isolated candidate APK remains temporary; a development package with verified provenance is a separate follow-up.
