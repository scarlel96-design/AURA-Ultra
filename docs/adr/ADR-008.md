# ADR-008 — 권한 상태와 관측 순서 분리
Status: PROPOSED / central design recommendation, owner agreement pending. 2026-11-28 KST. R-11/12/13/17/18/21/22; WO-17/20/21/22/23/33. No product implementation or integration authorization.
## Context
D01 payload immutability scoped GO, G01 independent development stopped. Both generic revision gate and numeric FSM intentionally accept higher revision with older measurement time after DENIED. This is data ordering, not authority. Do not change generic order solely to fix authority. SECURITY requires access stop after revoke. Existing tests preserve historical behavior until separately approved.
## Decision candidate
1. A single trusted coordinator per actual authority scope serializes permission checks and publication decisions. Scope includes authority, principal, permission/data category; map provider streams explicitly. Do not use SourceId alone. Unknown scope/authority denies protected use. Scope tokens are opaque and not user data.
2. Authority states UNKNOWN, GRANTED, DENIED. Only current verified SDK/platform authority can establish GRANTED. A potentially revoking notification immediately invalidates the affected scope and triggers a fresh check. A queued grant result from before invalidation cannot establish GRANTED. Locally ordered check tickets bind scope and current session; reject stale results, conflicting equal tickets fail closed. Do not trust callback timestamps or source-supplied revision for authority. Serialize event intake, not wall-clock times. Actual provider capability and authoritative result rules require official verification.
3. Use a non-reused session identity and per-scope non-wrapping generation. Rotate on authorization transitions/invalidation; retain on repeated verified same-state checks only if no unresolved invalidation occurred. Freeze acquisition provenance at start; it cannot be relabeled at completion. Only a trusted coordinator creates accepted provenance; a public DTO/token is not authentication. An async request carries scope/session/generation, and any publication derived from it carries the same provenance. On overflow block the scope until a verified non-reused session and fresh authority check. On restart begin UNKNOWN, invalidate prior session, suppress persisted results and recheck. Do not trust a stored grant alone. Session identity generation/persistence mechanism remains implementation decision; no reuse across restarts.
4. For protected data, check authority/provenance at acquisition start, result acceptance, cache read/write and final publication. Fail closed on missing/mismatched/unknown provenance or state. Validate payload, kind, unit, freshness and generic revision separately. Do not make every public unprotected stream depend on private authorization. Actual Domain functions remain pure and keep D01 immutability. Intelligence consumes only screened inputs; never derives permission from VALID or revision. At presentation boundary independently fence stale results, including LimitReached, PolicyRejected, resync, sequence/epoch changes and clock rollback. No changes to existing FSM thresholds.
5. On authority invalidation: deny further acquisitions immediately in the coordinator, cancel jobs best-effort, invalidate old generation, remove affected pending/cached/visible data, request supported consumer clear. Cancellation is not proof of invalidation; late completion must still fail the check. Publication and invalidation must be serialized or use equivalent atomic compare-and-commit. A process cannot guarantee instantaneous clearing on a disconnected or OS-cached consumer: verify supported invalidation, re-request/reconnect and measured latency in C01. Do not claim actual cleared display without evidence.
6. DENIED is a data status; a trusted permission denial establishes/retains denied authority. An untrusted or ambiguous denial is not a grant and triggers fail-closed recheck. ERROR and UNAVAILABLE withdraw affected publication per existing data order/TTL, without declaring actual authority revoked. Retain distinct reasons. No old queued result bypasses withdrawal via revision; data-order handling remains separately governed. No null-to-zero conversion. On verified regrant, only newly acquired current-generation data can publish; historical measurement observed before grant is allowed only when authorized source and approved retention/history policy permit the read. No old payload re-tagging. Persistent storage deletion/retention and cross-device authority remain gated.

## Alternatives
Timestamp alone rejects legitimate historical corrections and cannot prove current permission. Revision alone permits stale replay. Chosen candidate combines authority fence plus data order; introduces state lifecycle and cross-process synchronization. Avoid changing both modules at once; first agree exact boundary, then separately authorize one isolated pure contract candidate. Keep existing 88/108 test identities and 100000 seed. New suite registration central. Do not change generic higher-revision test assertion merely to claim fix; new protected boundary must reject replay.
